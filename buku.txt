## 🎯 FOKUS UTAMA PENELITIAN

### Bukan Software Development Methodology
- Jurnal **sama sekali tidak menyinggung** metodologi pengembangan software
- Tidak ada pembahasan tentang:
  - Software engineering practices
  - Development lifecycle
  - Project management
  - Quality assurance untuk software
  - Testing methodology untuk code

### Murni Evaluasi Algoritma
**Fokus Penelitian**:
1. Perbandingan kinerja algoritma rekomendasi:
   - Collaborative Filtering (User-based)
   - Fuzzy Logic (Content-based)
   - Hybrid Fuzzy-CF (Weighted Hybrid)

2. Evaluasi dengan metrik standar:
   - Mean Absolute Error (MAE)
   - Root Mean Square Error (RMSE)
   - Hit Rate
   - Statistical significance testing

3. Perbandingan dengan baseline algorithms:
   - Random Baseline
   - Most Popular
   - Average Rating
   - Item-Based CF

4. Analisis sensitivitas parameter:
   - Alpha parameter (α) pada rentang [0.0, 1.0]
   - K parameter pada Collaborative Filtering
   - Berbagai similarity methods

### Hasil Penelitian Utama
**Temuan Empiris** (dari final_evaluation_results.json):

| Algorithm | α | MAE | RMSE | Hit Rate |
|-----------|---|-----|------|----------|
| CF Only | 0.0 | 0.4419 | 0.5627 | 0.6582 ⭐ |
| Hybrid | 0.5 | 0.9585 | 1.1136 | 0.2579 |
| Fuzzy Only | 1.0 | 1.8003 | 2.0374 | 0.0956 |

**Statistical Significance Test**:
- P-value: 2.77e-15 (highly significant)
- Cohen's d: 15.12 (very large effect)
- **Kesimpulan**: CF Only secara signifikan lebih baik dari Hybrid

## 📝 ARGUMENTASI UNTUK JURNAL/BUKU

### Kenapa Prototyping/RAD Lebih Cocok

**1. Nature of Research = Experimental**
- Penelitian algoritma bersifat eksperimental
- Butuh trial-and-error untuk menemukan konfigurasi optimal
- Hasil aktual bisa berbeda dari hipotesis awal

**2. Real-World Data Required**
- Tidak bisa menggunakan simulated data
- Perlu deploy untuk mendapatkan data nyata
- Fast iteration antara implementasi → test → perbaikan

**3. Complex Algorithm Trade-offs**
- Banyak parameter yang perlu di-tune (α, K, weights)
- Tidak bisa diprediksi tanpa eksperimen
- Empirical testing lebih reliable daripada teori

**4. Adaptive System Requirements**
- Sistem perlu beradaptasi dengan kondisi data
- Adaptive alpha berdasarkan merchant rating count
- Butuh fleksibilitas yang tidak ada di pendekatan terstruktur

**5. Statistical Validation Emphasized**
- Fokus pada statistical significance testing
- Cross-validation dengan reproducibility
- Bukti empiris lebih penting daripada asumsi

### Bukan Waterfall Karena...

**Tidak Ada Evidence**:
- ❌ Requirement gathering terstruktur
- ❌ Design blueprint di awal
- ❌ Sequential development phases
- ❌ Formal testing phase terpisah

**Ada Evidence**:
- ✅ Langsung deploy awal Februari
- ✅ Iterasi berdasarkan hasil testing
- ✅ Perubahan signifikan pada sistem evaluasi (unified system)
- ✅ Fokus pada hasil empiris daripada planning
